# 跨阶段桥接目录

从已审阅的交互设计v2保留32条合同。它们是触发式选择，不是必走步骤。代号R对应Studio方法、C对应Companion问法、S对应Co-Scientist方法、X对应新增代码/执行桥。实际入口见 [research-workflow](../../skills/research-workflow/SKILL.md)。共同记录和上下文遵循 [research-contract](research-contract.md)。

### 4.1 Phase 0：六种检索与阅读桥接

| ID / 时机与方向 | 最小输入→交回产物 | 谁消费、怎样回流、何时停止 |
|---|---|---|
| **P0-1 缺锚点**：R-Query→C-Seed/X-Code→R-Query | 原话、文件入口、已知约束→1–3 个具体待查问题，锚点标用户提供/代码观察/猜测 | 为选定问题设计查询。过宽就局部澄清；已有明确对象就停访谈。缺锚点不是整个项目 KILL |
| **P0-2 同域召回饱和**：R-Query↔C-Brain | 当前操作对象、障碍、已有查询→源领域与目标领域的对象/操作映射、前提、失效点、原领域术语 | 独立跨域查询补进证据池；不无上限追加同义词。搜出噪声要回传哪里不相似；映射被否定即撤回 |
| **P0-3 异域材料进入阅读**：R-Triage↔C-Brain/R-Read | 命中材料、触发它的结构映射、待决问题→主题相关性＋研究用途＋要读的段落 | 异域机制、反例、测量论文、综述导航可被定向深读。源方法条件不同则交回迁移差异；无可说明用途才移出活跃集合，不删除原记录 |
| **P0-4 提名变成承重来源**：R-Cover→S-Ground→R-Diagnose/C-Brain | 论文身份、具体引用命题、提名理由、目标条件→身份核验；源领域主张支持核验；目标迁移未知项 | 两层核验不能合并。文献是真的，但目标条件未满足，则只引用已核部分。无法访问记未核；反驳了引用也不自动反驳整个候选 |
| **P0-5 争议决定读什么**：C-Critic/C-Strategy/S-Review→R-Query/R-Read→原请求方 | 一个足以改变决定的事实争议/危险前提、现有来源→定向检索或全文片段、条件和方向 | 只重评相关维度；评测争议优先 protocol/代码，机制争议优先 method。文献不能回答就转代码/探测，不继续堆阅读量 |
| **P0-6 后续阶段补证据**：任意步骤→R-Query/R-Cover/R-Read→原步骤 | 新算子、别名、反例、代码变化或无依据表述；已有材料索引→增量证据和受影响判断 | 改掉 coverage 只做一次的控制。回答当前问题后返回原步骤；动摇问题本身才转 P1-6。无需重新下载所有全文或跑完整 Phase0 |


**新增的桥接逻辑**：现有 RS 的身份解析主要用标题近似匹配，不能将其直接当作命题核验；异域用途、目标迁移前提以及任意阶段增量请求需要重新设计。原有连接器、缓存与来源记录可继续复用。

### 4.2 Phase 1：六种问题诊断桥接

| ID / 时机与方向 | 最小输入→交回产物 | 谁消费、怎样回流、何时停止 |
|---|---|---|
| **P1-1 意图发生变化**：C-Seed↔S-Goal↔R-Diagnose | 原话、旧目标、环境事实→硬约束/偏好/方案猜测/未知的短合同 | 所有消费者继承硬约束。无法满足就给冲突与可选路径；用户要求的实质变更交用户决定，不能用 departed 自动绕开 |
| **P1-2 gap 意义不明**：R-Diagnose↔C-Frame/C-Critic | 失败现象、最好已有方法、影响对象、证据状态→“若成立，会改变什么认识/能力”的条件式价值句 | RS 核实真实问题是否支持这项意义。价值依赖事实则转 P0-5/P1-4；只是写得不精彩不构成否决；没有具体价值才回选题 |
| **P1-3 共同前提/旁系解法**：R-Diagnose↔C-Brain→S-Ground | 方法谱系、残差、共同假设、原始出处→跨领域结构映射、可挑战前提、已解决部分 | 记忆祖先仅作查证线索；确认同条件已解决就撤 gap；只有类比就保留未核。不能限定只有近期论文叶子能产生科研问题 |
| **P1-4 瓶颈本身需要核验**：R-Diagnose→S-Review/X-Code→R-Diagnose | “问题存在”的命题、anchor 原文、代码版本/配置、数据/日志、替代解释→前提逐条核验与最便宜的反驳检查 | 已修复实现→限定旧版本；评测伪影→测量诊断；现象更窄→改范围。代码路径存在不代表运行经过；未执行不能声称已复现。真实代码输入是需新增的桥 |
| **P1-5 路径不足先分流**：R-Diagnose↔C-Strategy/C-Decide | 缺失究竟是文献、锚点、资源、可观测量还是价值→明确缺口和最近行动 | 文献少但有新现象可走观测路径；不可得资源调用 P2-5；问题已解决转应用/复现或换问题；暂不可测可 PARK。取消“少于五篇就失败”的普适门禁 |
| **P1-6 后续失败重开诊断**：R-Audit/X-Run/S-Evolve→R-Diagnose/C-Strategy | 被推翻命题、原始证据、旧 framing、幸存观测、可保留资产→退役命题＋仍成立部分＋新问题 | 换机制足够则回 Phase2；共同问题前提错误才改问题版本；被已有工作覆盖转 R-1。没有新证据/新可区分路线时不重复抽候选 |


**设计改变**：Verification 的对象可以是“问题成立的前提”，不必等有完整方法。Frame 在此是价值假设；文献与代码证据才决定事实。研究问题可以来自代码异常、旧方法在新条件下失效或新观测，不能被近期文献树的形状限定。

### 4.3 Phase 2：六种构造与演化桥接

| ID / 时机与方向 | 最小输入→交回产物 | 谁消费、怎样回流、何时停止 |
|---|---|---|
| **P2-1 朴素方案卡住**：R-Construct→C-Brain→P0-4/P0-6→R-Construct | 明确障碍、实际观测模型、代码接口、可用/排除信号、已试失败→异域求解映射与条件 | 先核机制/条件再具体化；不是只给一个领域名重新 brainstorm。无可核映射或前提被否定就停该分支 |
| **P2-2 候选实质互补**：R-Select/S-Compare→S-Evolve.combine→R-Construct/R-Probe | 两父候选及反证、共同问题/约束、输入输出→A 产出对象 O，B 使用 O 的交互与联合预测 | 两者高分或嵌入距离远不够。若不能命名 O、不能产生区别于亲本的预测、删除组件无损核心主张，则保持备选不组合 |
| **P2-3 方案过重或局部失败**：R-Probe/C-Critic→S-Evolve.simplify→R-Select/C-Critic | claim→步骤→预测依赖、失败部件、代码改动、资源→删减后的机制版本与丢失/保留的主张 | RS 做 removal/naive 检查，Companion 判断剩余贡献价值。若变成另一个问题，显式新建问题版本；空泛正确陈述不能算修复成功 |
| **P2-4 反例要求重构**：R-Probe/R-Audit→C-Brain/S-Evolve.out_of_box→R-Diagnose/R-Construct | 原句、脚本、合法实例、结果、歧义、structural_requirement→需要哪种新信号、哪些不可用、哪些资产可保留、替代机制/框架 | 单个实现问题局部修；跨不同候选的共同失败才挑战共同前提。不能靠换词或暗增资源逃避反例；无新增结构/信息则停止 |
| **P2-5 原实验不可行**：R-Spec/C-Strategy→S-Evolve.feasibility→R-Audit/X-Run | 固定机制、最强 rival、区分预测、代码/数据/仪器、预算→测试路线的新版本与代理有效性论证 | 新路线保持区分力才接纳；便宜但无区分力则标当前不可检验。机制也改了必须回构造；仅换测试路线不凭空制造新假设 |
| **P2-6 做得出但意义变弱**：R-Construct/R-Probe→C-Critic/C-Strategy→R-Diagnose或R-Construct | 最强基线、剩余差异、预期结果标记、实际用途、机会成本→一项最关键价值疑问与具体取舍 | 问题重要但机制没对上则改机制；观察到有价值新问题则改 Q；只有文案不好就进视图。不能因为“不像好故事”判技术错误 |


**15+31 资产不只服务生成**：C11 等前提检查可辅助 P1-3；C02 可在 P1-4 定义混杂、在 P2-5/R-3 设计独立 oracle 与受控测试、在 R-4 检查归因。子卡的失败教训可服务审查与反例构造。允许零张或一张，保留语料适用边界；例如某子卡强调 theorem，不能因此要求所有相关研究都必须有定理。

### 4.4 审查与实验：八种证据回流

| ID / 时机与方向 | 最小输入→交回产物 | 谁消费、怎样回流、何时停止 |
|---|---|---|
| **R-1 疑似被覆盖↔重新定位**：C-Critic/C-Strategy↔R-Collision→R-Construct/C-Strategy | 具体操作、疑似方法族、前提、原文、检索范围→包含关系/实质差异、可挽救部分 | 不只传 abandon。可转真实约束下改进、复现、边界发现；改变问题走 P1-6。无有价值差异则停止，不能换名伪装创新 |
| **R-2 引用方向争议**：任一判断→S-Ground→原判断 | 原命题、原文位置、系统与条件；隐藏旧总分→支持/部分/反对/未找到/不可达/未引证及理由 | 只撤回依赖错误来源的判断，不自动证明相反结论。争议核完即停，除非发现系统性同类错误 |
| **R-3 风险优先→一份区分测试**：C-Critic/C-Decide→S-Review/R-Audit→X-Run | 最危险前提、两个解释、可观察量、代码、真实资源→干预/对照/读数/预测分叉/失败解释 | Companion选值得查什么；Co查是否区分；RS查负对照是否作用到下游结果；共同修改一份测试。只需支持下一决定，不默认整套实验矩阵 |
| **R-4 执行反证↔反证有效性**：R-Probe/X-Run→R-Audit/S-Review→必要时窄复核 | 命题原文、版本、代码、实例、前提、输出、范围；隐藏总评→逐条保留/反驳/待查 | 推翻反例需具体形式化/算术/合法性问题。有效单例可否定全称保证；合成收益不能证明真实平均收益。争议结清即停，不默认多人重审整卡 |
| **R-5 具体问题→修补→局部重检**：R-Audit/S-Review→R-Revise/S-Evolve→有关检查 | 问题、原证据、候选版本、允许改动、硬约束→改动说明、影响的主张/测试 | 引文问题回 grounding；控制组改动回 testability；机制改动回 coherence/有关查重；仅文案就重渲染。没有实质变化不循环评分 |
| **R-6 两解释难分高低**：S-Compare/多位 reviewer→S-Review/R-Audit | 两完整机制、同一事实包、支持/反证、共同约束；隐藏 Elo/票数→共同解释、分歧预测、下一观察 | 有区分实验就转 R-3；暂不能区分则并存/搁置。确需资源优先级交 C-Strategy，不能强制选科学赢家 |
| **R-7 技术审查后分配投入**：R-Audit/S-Review→C-Strategy/C-Decide | 当前贡献、代价、未决风险、替代路线、用户目标→下一投入、放弃什么、重访条件 | advance 不是投资理由；PARK 也不是机制错误。下一步资源决定明确就停；不改变历史证据 |
| **R-8 真实结果分诊**：X-Run→S-Review→X-Code/R-Construct/P2-5/P1-6 | 当时预测、实际配置、原始结果、异常、比较公平性→测量故障/机制反证/区分不足/局部支持/未知 | 测量坏先修工程；机制失败回构造；区分不足改测试；重要异常可生新问题。同步 C-Strategy 更新投入，不一律再生成或调参 |


**这里至少有五种审查对象**：投入价值、机制、贡献差异、实验区分力、证据支持。前四种判断需要第五种服务。可以复用一个审查入口，但须明确这次审哪件事；不能做一个大总分替代它们。

### 4.5 成卡、总结与恢复：六种末端反哺

| ID / 时机与方向 | 最小输入→交回产物 | 谁消费、怎样回流、何时停止 |
|---|---|---|
| **O-1 写不清贡献**：R-Card/C-Frame→C-Critic/R-Diagnose/R-Construct | 原问题、机制、最近邻限制、条件式价值→究竟是表达问题、价值不明还是机制不匹配 | 仅表达不清就改视图；目标—机制错配回 P1/P2；不为好听扩大范围。与 P1-2 共用价值检查，只是触发时机不同 |
| **O-2 规格缺口**：R-Spec→X-Code/R-Construct/R-Probe | 步骤/公式/输入输出、claims、代码对象与数据类型→缺定义、需作者选择、公式错或接口不存在 | 文档遗漏直接补；负载设计选择回作者；算错回 coherence；资源不足走 P2-5。审计员不能暗自补关键机制，仅在渲染文本里改变研究 |
| **O-3 卡片三轴诊断**：R-Quality→有关能力 | 同版本 problem/method/reasons/证据引用；不带旧分数→带位置的具体薄弱点 | A真实性未知→查证；A价值弱→策略；B逻辑→coherence；B资源→feasibility；C错配→诊断/构造。只在实质输入改变后复评，避免润色刷分 |
| **O-4 假设性结论转成果结论**：C-Frame/R-Card↔S-Ground/S-Review↔C-Strategy | 旧预期、冻结预测、真实结果、对照、范围、异常和反例→每条主张现在支持到哪里 | 只收窄措辞就更新视图；想保留更强主张则新建待解问题/测试。发现侧结果可转向，但保留原失败，不能追溯改预言 |
| **O-5 多候选出现共同弱点**：S-Overview→R-Query/R-Diagnose/R-Construct/C-Brain | 各弱点原证据、适用对象、反例、版本→带范围的经验与下一动作 | 漏方法族→补检索；共同不可识别→改问题；已失败前提→约束构造；新结构→跨域召回。无具体依据的共同偏好不升为全局规则 |
| **O-6 人/读者反馈与 PARK 恢复**：S-Overview/用户→有关能力 | 反馈原文、角色、目标版本、生效时间、旧重访条件→采用/待查/不适用及理由、受影响动作 | 事实质疑回 grounding；目标变更回 P1；资源变更回 P2-5；反例回 R-4；展示偏好只改视图。保存反馈不等于已消费，更不自动启动新预算或监控 |


这是 **32 条可触发的桥接合同**。相似检查共享同一份方法定义，例如 P1-2 与 O-1 共用价值检查，P1-5/O-2 引用 P2-5 的可行性检查，R-3 是各处共用的测试设计合同。32 条连接不意味着32个服务，也不意味着一次研究要运行32步。
