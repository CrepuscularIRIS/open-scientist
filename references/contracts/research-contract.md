# 共同研究合同

这是所有技能的共享语义，不是一条必须逐项走完的流水线。每次只加载当前问题需要的技能、原始材料与方法参考。原始归档位于 `vendor/`，用于出处比较；其中旧宿主命令、固定面板、默认预算与阶段门禁不构成当前执行指令。

## 五类记录，一个项目事实源

| kind | 保存什么 | 必须分开的概念 |
|---|---|---|
| project | 原问题、硬约束、偏好、资源事实、未知、问题版本 Q | 用户要求、模型建议、环境事实不能混在一起 |
| candidate | 机制 H、父候选、前提、主张、可区分预测 | 设计完整不等于已经有效 |
| material | 论文、代码、数据、日志、原始输出的位置与出处 | 身份已核、内容已读、支持目标主张是三回事 |
| activity | 计划 T、使用的版本、执行边界、状态和原始产物 | plan、running、completed、failed 不同；completed 不等于科学通过 |
| assessment | finding、decision、feedback、disposition | 机制判断、证据方向、投入决定、反馈消费各自有理由 |

实际 API 以 [record-api](../../docs/record-api.md) 为准；不要把文中的简记当作可直接提交的 JSON。引用统一 `{id, version}`，引用的对象必须先写入同一项目。每次更新提供 `expected_version`，发生冲突先重新读取并合并事实，不能无条件覆盖。无 MCP 时使用同一 CLI，见 API 文档；仍无法使用时保留带版本的 Markdown 交接并明确尚未入库。

研究项目根目录必须由当前用户任务或已明确的工作区得出，不能默认写到插件安装目录。记录后端只保存 Agent 提交的资料并检查结构、引用与版本；不自动验证科学结论，不拥有命令执行权。

## Q / H / T 与文案视图

- Q 变化：研究对象、条件、测量目标或问题前提改变，写 project 新版本。
- H 变化：机制、承重前提、关键参数或核心主张改变，写 candidate 新版本；保留父版本与改动理由。
- T 变化：固定 H 下改变实验、代理系统或测试预算，写 activity 新计划；尚未运行的 plan 可以追加版本，已运行/结束的测试需新 activity ID。已经执行的输入、事先预测与结果永不回写。
- View 变化：解释、排版或摘要改变，不改变研究对象。表达时发现缺失机制，创建 finding 并返回 H 修订，不能在 Card 内暗补。

“版本改变”不意味着全量重跑。列出旧判断所依赖的前提与材料：引用拼写修正只核身份/相关表述；选择策略改变则重查数据流、反例、基线公平性、查新与有关预测。旧结论保留历史，但不得自动继承为新版本有效。后端的 stale 提示是版本依赖信号，语义影响仍由 Agent 判断。

## 每次交接的六项信息

1. 触发：出现了什么新问题、证据或用户反馈。
2. 待决问题：本次只要回答哪个具体问题。
3. 基于版本：Q/H/T 和用户硬约束。
4. 必须读取：原始来源、代码位置、执行反例、未知项，不能只传润色后的摘要。
5. 允许改变：问题、机制、测试、投入选择，或仅文案。
6. 交回：发现、影响范围、具体下一动作、未能回答的缺口；对应反馈采用/待查/不适用及理由。

## 四种科学判断与投入决定

分别回答：问题为什么值得、机制能否兑现、相对最近工作新增什么、测试能否区分解释；另查来源究竟支持哪条主张。缺证据不等于错误，没检到不等于新颖，技术正确不等于值得继续。`pursue/refine/park/kill` 是投入选择，必须附原因；`park` 要有可检查的重访条件，不自行创建监控或重启作业。

## 审查上下文

独立首评可以隐藏作者、旧总分、推荐结论和叙事包装，但必须继承硬约束、准确版本、原始事实和反证。针对修订的复核读旧 finding、delta 与受影响内容；争议核查只裁定形式化、算术、实例合法性或出处范围。看过旧评分的复核不能声称独立盲评。参考 [review-context](review-context.md)。

## 默认边界与终止条件

默认单 Agent 可运行；分工只在任务授权且有实际收益时使用。知识资产允许大量保留，当前上下文只加载相关部分。没有新材料、不同预测或可执行的判别动作时停止该回路，说明保留了什么与缺少什么。无需固定论文数、模式数、评委数、回合数或 Elo；未知预算保持未知，下一步先做已授权的廉价调查。
