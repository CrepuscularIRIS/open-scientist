# Decision card

Audience: A researcher deciding the next investment or resuming a project.

This is an optional view of the same project records, not a new source of truth or a mandatory output. Render only fields useful to the current request; preserve uncertainty and decisive evidence. Use the [shared contract](../contracts/research-contract.md) and [record API](../../docs/record-api.md).

## Basis
Exact Q/H/T and relevant material/assessment references; date of view.

## Decision and subject
State pursue/refine/park/kill for the exact candidate or project version.

## Why now
Name the new result, constraint, source, or resolved uncertainty that changes the choice.
State the strongest argument against this choice, including low-ranked counterevidence.

## Scientific status
Separate what is supported, contradicted, contested, and unknown by claim and scope.
The investment decision does not create a scientific finding.

## Next action or revisit condition
For pursue: one bounded action; for refine: named deficiency and responsible skill.
For park: checkable condition; for kill: evidence and assets worth preserving.
Do not automatically schedule a monitor or restart a historical process.

## Feedback disposition
Identify relevant feedback, adopted/deferred/rejected/superseded rationale, and exact outputs.
A recorded recommendation is not proof that execution or feedback consumption occurred.

## View boundary
Pure wording or translation changes stay in this view. Scientific changes return to the owning skill and appropriate version; never repair a missing method invisibly in prose.
