# Execution card

Audience: An agent executing a bounded authorized test.

This is an optional view of the same project records, not a new source of truth or a mandatory output. Render only fields useful to the current request; preserve uncertainty and decisive evidence. Use the [shared contract](../contracts/research-contract.md) and [record API](../../docs/record-api.md).

## Basis
Exact Q/H/T and relevant material/assessment references; date of view.

## Test purpose
Identify the exact H/claim and competing explanation this test can distinguish.

## Inputs and plan
Give code/configuration/data versions, observation unit, intervention, comparison, and metric.
Reference a plan T before execution when claiming preregistration.

## Predictions and stopping
State distinguishable outcomes, failure interpretations, and stop conditions before running.
Distinguish execution failure from a scientifically valid negative result.

## Resources and authorization
State known environment, cost estimate with basis, unknowns, and authorized execution boundary.
A cheap proxy identifies its transfer assumptions and lost discrimination, if any.

## Result record
After execution link raw outputs and record actual status.
Preserve the prior plan; corrections append history and a rerun gets a new activity.

## View boundary
Pure wording or translation changes stay in this view. Scientific changes return to the owning skill and appropriate version; never repair a missing method invisibly in prose.
