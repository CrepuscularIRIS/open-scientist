# Construction card

Audience: An agent or researcher implementing a precise candidate.

This is an optional view of the same project records, not a new source of truth or a mandatory output. Render only fields useful to the current request; preserve uncertainty and decisive evidence. Use the [shared contract](../contracts/research-contract.md) and [record API](../../docs/record-api.md).

## Basis
Exact Q/H/T and relevant material/assessment references; date of view.

## Mechanism and claim
State exact H version, claim IDs, assumptions, and the problem Q version.

## Data and code interface
Identify inputs, units, availability times, transformations, and outputs.
Link the actual code version and material records where available.
Mark proposed interfaces separately from implemented ones.

## Method steps
For each load-bearing step: operation, object, estimator/algorithm, input, output, and claim linkage.
Place equations beside their operation and cite the source of free constants.

## Open decisions
List missing specifications with their scientific consequence and who must decide.
A proposed normalizer, estimator, parameter, or oracle does not silently become part of H.

## Checks and handoff
List relevant counterexamples, specification checks, and targeted implementation/test actions.
Report environment feasibility separately from specification completeness.

## View boundary
Pure wording or translation changes stay in this view. Scientific changes return to the owning skill and appropriate version; never repair a missing method invisibly in prose.
