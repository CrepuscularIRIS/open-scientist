# Comparing hypotheses without manufacturing a winner

A comparison answers a stated decision question. It may identify which experiment to fund next, which mechanism better explains current evidence, or which pair of predictions would be most informative to separate. Those are different comparisons.

## When a comparison is useful

Compare candidates when they address the same decision and the difference could change the next action. Both need enough specification and evidence to make that comparison meaningful. If one is missing its central operation, resolve that first or explicitly compare readiness rather than scientific quality.

Near-duplicates are not useful scientific rivals. Inspect operations and predictions, not an embedding cluster alone. Similarity may suggest duplication but cannot establish mechanistic equivalence.

There is no required Elo, tournament membership or number of debate turns. A single comparison can be useful when its deciding evidence is clear. A longer structured debate is useful only when it exposes a real unresolved premise or different prediction.

## Fetch the substance

Read both candidates in full with their exact project constraints, code/experiment evidence and relevant reviews. A partial card can hide the premise that changes a result.

For an independent comparison, hide previous scores, ranks, author/model identities and recommendations. Preserve actual evidence from reviews, including negative results. For a cumulative comparison, disclose that prior judgments were visible.

When sources disagree, keep their provenance and scope rather than averaging their conclusions. If one candidate is better documented rather than better supported, say so; prose quality is not scientific evidence.

## State the comparison question

Choose one question before weighing differences:

- Which claim currently has stronger evidence, under the same stated scope?
- Which candidate offers a meaningful contribution beyond verified prior work?
- Which next test offers useful discrimination within the available resources?
- Which project is worth pursuing given the user's goals and opportunity cost?

The last question belongs to research-decide. Scientific comparison supplies its findings but does not silently turn them into a global ranking.

## Compare on concrete criteria

**Correctness and evidence:** can each claim be true given its definitions and the inspected evidence? Name any decisive contradiction; novelty or excitement cannot cancel it.

**Contribution:** what is new relative to actual prior work? A mechanism can be correct and already known; another can be new and currently unsupported.

**Testability:** is there an observation that distinguishes the explanations? Use the shared [falsification method](falsification_reaudit.md), including each rival's prediction.

**Specificity:** are the operations and assumptions stated well enough to act on? Reward useful definition, not verbosity or a larger card.

**Feasibility:** can the discriminating test run with the real resources? A cheaper test can justify investigating a candidate first without making its mechanism more likely to be true.

The user's explicit research goals may prioritize different decision criteria. Preserve scientific evidence boundaries even when investment priorities differ.

## Structured disagreement when needed

State each candidate and its strongest evidence fairly. Give the strongest objection to each. Where reviews disagree, identify the exact premise, source mapping or numerical claim at issue.

A simulated dialogue is a reasoning aid, not multiple independent experts. Do not count its turns as votes or independent confirmations.

End with the deciding evidence or a disagreement map: observations both explain, observations on which predictions diverge, and the cheapest admissible next check. A tie or unresolved comparison is a valid result.

If both hypotheses predict all currently available observations, forcing a winner adds confidence without information. Keep them both live, park one for resource reasons with that reason explicit, or design a new test.

## Output and records

Record claim-specific findings with exact references and material evidence. When the comparison leads to an investment choice, record a separate decision with rationale and revisit conditions if parked.

A useful comparison note contains the question, shared conditions, differences that matter, evidence/uncertainty, and the next discriminating action. Do not create a new ranking record kind or submit an unsupported Elo field to the shared API.

After new evidence, compare only the claims or criteria whose inputs changed. Keep previous comparisons as historical rather than updating them to make old decisions appear foresighted.

## Stopping

Stop when the next action is clear or the remaining scientific uncertainty is explicit. Do not run repeated matches merely to make a list tidier. If a named source or test could resolve the disagreement, route to research-retrieve, research-review adjudication, or research-test.
