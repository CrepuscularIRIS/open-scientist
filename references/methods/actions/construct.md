# Research Construct — 把方向构造成可检查的方法

将已选方向写成可以理解、实现和反驳的机制，而不是先写完整论文式 Card。
研究深度来自解决真实障碍，不来自模块数量、模式标签或繁复字段。
机制规格 H、实验计划 T 与已执行证据分开；构造完成不意味着方法有效。

先读 [共同研究合同](../../contracts/research-contract.md) 和 [record-api](../../../docs/record-api.md)。
主要细节在 [RS 完整构造方法](../../methods/ideate_generate.md)。

## 输入与进入条件

| 输入 | 本轮作用 |
|---|---|
| Q 版本 | 问题对象、条件、量、价值和用户硬约束 |
| 方向/父候选 | 核心操作、尚未绑定的替代、组合接口 |
| 最近邻材料 | 原方法实际做到什么、适用条件与未核差异 |
| 代码与数据 | 接口、可用信息、张量/状态形状、实际路径与权限 |
| 关键前提 | 支持/反对/未知，尤其观察模型与选择过程 |
| 既有 finding | 原反例、审查理由、需保留的部件和不能重犯的错误 |
| 资源事实 | 可得模型/数据/计算、预算未知项、授权边界 |

如果不能说清要解决什么，返回 [research-diagnose](diagnose.md)。
如果只是润色文字，进入 [research-report](report.md)，不要借机发明算法。

## 构造顺序

### 1. 确定承重产物与本轮范围

问题需要的是一个构造、可识别性结论、测量原语、可检验解释还是反例？
说明产物如何回答 Q；不要用“一个框架”替代具体贡献。
用户明确要求的产物类型继续遵守；证据建议不同目标时交具体备选供用户决定。
选择一个当前最有希望兑现的机制即可，替代方向保留为明确备选。
如果父候选失败，先列失败前提与可保留内容，再开始修订。

### 2. 读取与实例化战术，而非模仿表面

有合适 RS 子模式时，读 `tactical_pattern`、`Step-by-Step`、适用条件和拒绝教训。
将抽象操作落在当前对象上，写出每步为何需要。
没有合适子模式就直接构造，不强行选择最近的分类。
子卡论文是例子，不是当前问题的证据或被允许复制的创新。
领域距离远时注明映射条件；不能靠一个 C 编号完成机制论证。

### 3. 建立承重前提表

逐条列出机制成立所需的数学、经验、系统和访问条件。
每条注明依据；只是押注的前提标为“未验证—检验目标”。
输入来自采样/观测时，说明抽样、筛选、遗漏、反馈、非独立性与泄漏可能。
区分训练可见、验证可见、测试时可见的信息。
纯构造不消费采样信号时，可以明确“观察模型不适用”，不制造数据假设。
代码现实若推翻前提，改机制或返回 Q，不把非法 oracle 写进实现。

### 4. 需要估计时先定义 estimand

明确要估计的精确量、总体、过程、条件与时间尺度。
再说明算法实际计算的统计量与目标量的关系。
定义域、单位、选择偏差和自适应采样都可能改变这个关系。
不要把“可计算的代理”直接命名为真实不确定性、因果效应或全局性能。
若只能估计较弱目标，写清较弱目标及它能支持的结论。

### 5. 先做朴素基线审计

给出最直接、可运行原则上成立的方案，使用同样的信息和约束。
然后诚实选择以下情形之一：

- 它依赖当前条件下不成立的前提：命名障碍，新机制必须直接处理它。
- 它已经有效且大家知道：当前新增可能很小，说明真实增量或改设计。
- 它有效但领域误以为无效：核验该共同信念，才可能成为反直觉简化贡献。

不能故意削弱基线、隐去合理调参或只比较实现错误。
若处理障碍只需另一领域教科书工具，解释当前结构为何仍需新工作。
没有这种新增结构时，诚实按应用/复现表述，不贬低应用价值也不冒充方法创新。

### 6. 写出可计算的核心对象

定义每个输入、来源、单位、索引、权重与自由参数。
模型内读数、额外计算、外部标注、理想 oracle 分别标识。
当一个量涉及层集合/窗口/选择规则，明确选择由谁、何时、根据什么决定。
参数未确定时命名并保留待决规则，不为让文档完整编一个默认值。
可提出初始值与选择理由，但它是设计提议，不是已验证最优。
任何信息不可取得都构成具体缺口，不能藏在符号里。

### 7. 写代码路径级步骤

按执行顺序说明每步计算/修改什么、输入从哪里来、输出被谁消费。
已有 repo 时附相关入口/模块/调用位置与检查过的版本。
新代码路径注明拟新增，不写成已存在或已运行。
如果干预改变一个中间量，继续追到下游任务输出，避免只改变记账数值。
多个组件共享对象时命名对象；串联时说明 A→O→B 的实际数据流。
步骤数按机制需要，不为了模板拆成固定数量。

### 8. 兑现贡献强度

保证级词语如无偏、精确、最优需要紧邻其假设和相应推导。
只有经验可验证时用经验主张；单个小例运行通过不证明总体改善。
强主张可以保留为明确待证目标，不因保守而删掉有价值的问题。
已有合法反例若落在原全称命题范围内，原命题应标被反驳。
修改范围产生新 H；不得覆盖旧预测，或用后改定义声称原反例无效。

### 9. 设计真正区分机制的预测

说明最小程序、可获得系统/数据、测量量和预期方向。
命名承重变量，以及能削弱/打乱其作用的干预。
观察应到下游价值指标，不只检查被干预变量自己变成零。
将最强替代解释放在旁边：如果它也预测同样现象，该测试还不够区分。
必要时提出正控制或理想上界，但不能把 oracle 的可行性等同实际方法。
数字门槛需要理论推导、已测资料或明确决策成本依据；未校准值标待定。
不为了“可证伪”凭空写一个成功百分比。

### 10. 给资源与执行路径定范围

列可命名、可访问的模型、数据、工具及访问级别。
“模型存在”不代表本项目可以拿到梯度、权重、授权数据或付费额度。
需要自建资料时说明规模、人工/计算成本和未完成状态。
未知预算保持未知，按最小可区分动作估计 GPU/CPU/API/人工成本。
低成本代理若改变适用条件，明确它只是代理，不承诺回答完整 Q。
昂贵执行按已有授权边界处理；本技能不会因为写好步骤就启动作业。

### 11. 对照最近邻与跨领域别名

对最近工作逐项比较条件、可用信息、操作、产物和保证。
一句差异必须说明多构造/测量/推导了什么，而不是换了模式名称。
检查几乎已有这项贡献的工作缺了哪一步，全文不足则标差异未核。
从诊断已有旁系家族生成异域查询，不在此丢掉已经找到的重要线索。
没有具体区别时修改新颖性主张，而不是润色标题。

### 12. 交接规格、待核项和最小动作

规格自洽性、可实现性和科学效果是不同问题。
可交 [research-code](code.md) 核对接口/实现位置。
可交 [research-test](test.md) 执行获授权的最小检查。
需要独立挑战时交 [research-review](review.md)，携带原反证与约束。
没有核心机制、合法输入或可区分预测时，停止扩写并返回具体缺口。

## 预期产物与写入方式

候选规格包括：问题引用、核心机制、前提、estimand（如适用）、朴素基线、实现步骤、差异和预测。
保留明确 claim_id；后续 finding 绑定它，避免审查只评论整篇吸引力。
使用 API 的 candidate `mechanism` 承载完整方法文本，`claims` 保存稳定主张映射。
`assumptions` 与 `predictions` 分列；来源先写 material，再由 assessment finding 绑定支持关系。
`parents` 记录实际父候选；变更用 `expected_version`，保留机制 delta。
测试设计写 activity 的 plan；没有运行就不是 completed，运行失败不是负科学结果。
不要将方法参考里的 JSON 风格提纲直接提交到严格 API。

## 分支与回流

| 发现 | 最小影响范围 | 去向 |
|---|---|---|
| 文献引用修正且机制不变 | 对应来源/判断 | retrieve/review |
| 非法信息或代码接口缺口 | 先 H；若 Q 前提错误再 Q | code/diagnose |
| 朴素方法已足够 | 贡献边界或另一个 H | ideate/decide |
| 定义不完备 | 当前 H 的具体步骤 | construct |
| 更便宜测试保留区分力 | 新 T，不改 H | test |
| 反例反驳原全称主张 | 原 H finding + 新 H | review/evolve |
| 用户目标必须改变 | 备选方案与代价 | 用户决定 |

## 情境例：从自适应日志估计成功率

方向是“用最近成功记录估计每项任务的成功率”。
先定义目标是全任务分布成功率，还是被当前策略选中任务的条件成功率。
若日志只记录被选择的任务，简单平均可能估计后者，不能暗称前者。
核对代码是否记录选择概率、未选择任务和选择时可见信息。
如果这些信息缺失，不能凭空加入逆概率权重；先确定可识别目标或新记录方案。
定义合法估计量和朴素对照，再提出改变选择机制时哪些观测能区分解释。
仅修复 Card 文案时不新增一个未定义的 reward normalizer；新机制应有新版本。

## 常见失败与来源

- 用新模块掩盖朴素方案已足够：先完成同条件基线审计。
- 参数一律补默认值：未决值保留命名的设计问题。
- 干预 X 后只看 X：补下游指标及竞争解释预测。
- 只有详细步骤就称可行：核实际权限、代码、数据和成本。
- 修改实验解释就声称原反例失效：保留旧 H/T 与反证。
- 三份长卡替代机制：当前只生成回答下一问题需要的规格。
