# Research Retrieve — 按问题查找、阅读与回流证据

本技能把一个待决问题变成可追溯的资料与差异判断。
可以在选题、诊断、方法构造、实验后、审查或写作时进入。
交付的是“查了什么、实际读到什么、现在能判断什么、还有什么未知”。
检索命中、来源身份、来源支持、跨域迁移是不同的判断。

## 入口与最小上下文

先确定项目目录和当前需要回答的问题，不把安装目录当项目。
已有记录时，读取对应 project/candidate 的确切版本及其材料引用。
需要恢复上下文时用 `records_context`；它返回完整上下文，宿主按当前问题选读。
保留不利材料；此前的总分、PURSUE/KILL 或模型身份不是检索依据。
已有充分输入就直接工作，不重复访谈。

最小输入：

- 用户原问题；不能只保留经过改写的关键词。
- 正在影响的候选/主张/评测或代码问题，以及准确版本。
- 已知论文、代码路径、数据、基线和真实资源约束。
- 已查范围、失败来源、仍未回答的问题；没有就明确尚未查。
- 本轮预算或停止条件：回答哪一问题后就足够。

| 当前需要 | 本轮重点 | 返回给谁 |
|---|---|---|
| 方向过宽、没有研究对象 | 从已有项目和用户关切定位对象 | `research-workflow` 的 intake 或 `research-ideate` |
| 对问题的不同解释 | 查前提、反例、测量条件 | 诊断/探索动作 |
| 方法具体但可能已有 | 异名同构与最近邻比较 | 方法构造/审查动作 |
| 结果与论文预期冲突 | 原始设置、实现和实验条件 | 验证/诊断动作 |
| 一个引用换了来源 | 只核对应主张与依赖 | 审查/记录更新 |

上表是调用意图，不要求先依次执行其他技能。
不知道硬约束时保留未知；不要从文献规模推断用户拥有相同资源。

## 1. 把检索问题拆清楚

写一段短 brief：我们要决定什么，什么发现会改变下一步。
若查新，分清研究问题与声称的新贡献，不能把同一句话写两遍。
拆出 framing、mechanism、insight、domain，作为比较维度而非计分轴。
另外列出允许的信息、前提、目标、保证与实际测量范围。
现有方法在同一信息条件下已经做到什么，是最重要的比较之一。
用户提出的方案可作为待检验线索；明确硬约束才是搜索边界。

先读 [intent-recognition](../../references/methods/intent-recognition.md)。
查询按需要覆盖下列视角，不要求每轮四条齐全：

1. 原问题/领域对象：目标社区如何描述它。
2. 方法签名：具体算子、数据结构、信号或步骤。
3. 相似问题：已有基线与近邻研究如何称呼它。
4. 解决方案词汇：已经解决该瓶颈的论文可能如何命名。
5. 跨社区别名：同一机制在其他领域的名称。

不要让同一词的近义改写占满有限查询预算。
每个查询说明它补哪个盲区；结果重叠时可以合并。
每次实际调用最多 8 条，词项是 AND 关系，不把长自然语言整句塞入。
指定日期时说明理由；旧的承重方法不因超过 24 个月而被排除。
点名论文/系统应单独解析名称与来源，不能靠宽泛关键词碰运气。

## 2. 执行本地语料与 arXiv 检索

默认只有本地索引与 arXiv；不自动启用 S2/OpenAlex 等连接器。
脚本在插件根目录的 `scripts/` 下，即本技能目录的 `../../scripts/search_papers.py`。
当前工作目录通常是用户项目而不是插件目录，所以调用时使用绝对路径（Codex 与 Claude Code 相同）：

```bash
python3 <plugin-root>/scripts/search_papers.py \
  --queries 'memory selection|vision language action' \
  --sources local arxiv --max-papers 20 \
  --start-year 2024 --end-year 2026 \
  --timeout 10 --budget-seconds 25 --json /tmp/paper-search.json
```

查询和年份是示例，按 brief 调整；省略年份即不设该边界。
省略 sources 仍为 local+arxiv；离线使用 `--sources local`。
`PAPER_SEARCH_LOCAL_DB` 指向已有索引，默认 `/data/paper_index/local_papers.db`。
脚本以只读 SQLite 打开索引，不建库、不全表加载、不复制 PDF。
返回的 `pdf_path` 是可读位置线索；先确认实际存在，再读取。
stdout 总是 JSON；`--json` 可选保存相同报告。
详细接口、schema 和时间预算边界见 [search-adapter](../../docs/search-adapter.md)。

| 返回情况 | 正确处理 |
|---|---|
| local `missing_index` | 本机缺索引，保留覆盖缺口；不能写“本地无相关工作” |
| local `empty` | 当前关键词和范围无命中；可调整关键术语 |
| local `error` | 读库/结构/预算失败，不作为空检索 |
| arxiv `empty` | 有效 API 响应无命中，不证明新颖 |
| arxiv `timeout` / `unavailable` | 本次渠道未完成，保留已有本地结果 |
| arxiv `rate_limited` | 停止即时重试；使用已有材料或结束于覆盖不足 |
| `ok` 且 `partial: true` | 可能只有部分查询成功，逐项读 attempts |
| coverage `limited: true` | 查询或展示被截断；不能宣称穷尽 |

进程退出 0 只证明报告生成；必须读 source status 和 coverage。
本调用按顺序控制 arXiv 间隔；不要开多个并行进程绕过间隔。
时间预算限制新任务启动，网络系统调用可能超时外溢；记录实际 elapsed。
如关键原始来源已知，可用宿主工具直接打开官方论文页、作者仓库或引用链。
这属于任务相关的原始来源读取，不是自动开启其他聚合提供商。
访问失败如实保留；不循环重试到超出预算。

## 3. 整理命中与提名，按用途选读

脚本按 DOI、去版本 arXiv ID、标准化标题去重并保留 provenance。
同名去重是线索级启发式；身份存疑时查看每个原始引用。
模型回忆或 Brainstormer 的跨域线索另记为“提名”，不能伪装成 API 命中。
提名可带标题/作者/ID 猜测，但未知字段留空；来源未解不等于不存在。
身份解析看原站标题、作者、版本、DOI/ID 的对应关系。
找到真实论文仍未证明“它支持这条主张”。

阅读 [relevance-and-reading](../../references/methods/relevance-and-reading.md)。
每项至少判断：主题相关性、对本轮的用途、当前证据层级。
用途包括同域基线、异域机制、反例、测量方法、综述导航、来源身份。
同域不自动重要，异域不自动无关，综述可导航但不冒充原始实验。
不能因为 outside_taxonomy、未命中 15 模式或领域不熟悉而剔除。
只有确实与当前问题无可说明用途的项才移出活跃阅读集合。
保留它的原始引用和移出原因，未来问题改变时可重新使用。

从最可能改变下一决定的材料开始，不要求至少 5 篇或深读固定 3–7 篇。
关键机制的模糊摘要、反证、强基线和目标项目代码都可能先读。
纯关键词相似不能证明机制相同；作者的“首次”声明不能代替查新。
把反对和支持当前方案的来源放在同一证据标准下。

## 4. 按待决问题阅读原文

读取实际文件或原始页面，优先复用现有 PDF/文本，不批量复制全文。
摘要只支持摘要范围；网页摘要/模型总结不能当作已读方法正文。
不同问题决定读不同片段：

- 机制相同吗：算法、公式、数据流、输入可用时点。
- 某前提必要吗：定理条件、证明、反例、限制。
- 分数可比吗：评测协议、数据划分、基线配置、appendix。
- 能迁到当前项目吗：源设置、目标代码接口、资源与观测差异。
- 谁先提出：版本、正式出处与原始贡献段落。

提取能决定当前问题的短原句或精确页/节/代码行，记录实际读取范围。
固定“三段摘录”不是通过标准；足以判断就停，缺关键条件就标未知。
无法读到正文时记录 abstract-only/unreachable 及由此受限的判断。
来源事实与目标迁移分开：

1. **身份**：这是什么论文/代码版本，是否确实找到。
2. **源支持**：原文是否支持该主张、方向、对象和强度。
3. **目标适用**：当前项目是否满足相同前提；未检验则仍为假设。

对重要支持关系可转给独立查证/审查动作；交接原文与约束，隐藏先前总评。
独立性不意味着隐去反例、失败记录或不利来源。

## 5. 比较与定向反馈

有明确新颖性主张时使用 [collision-check](../../references/methods/collision-check.md)。
比较对象、可用信息、目标、操作、假设、保证和实测范围。
异名同构要指出哪一步对应；同词不同机制要指出哪个条件改变。
没有固定“重合轴数→新颖性等级”；没有命中时返回覆盖范围与未知。
可写 delta，但收益未验证时写“拟检验是否”，不能写成已取得效果。

| 发现 | 回流内容 | 不需要做的事 |
|---|---|---|
| 异域机制可能迁移 | 操作映射、成立条件、断点 | 整体重跑选题流程 |
| 原问题已有解决办法 | 原文差异与仍未覆盖的设置 | 为保留旧方案发明 gap |
| 来源推翻关键假设 | 对应主张版本、原文、范围 | 用总体高分抵消反证 |
| 实现与论文输入不同 | 代码/论文证据与待诊断差异 | 未核就宣布泄漏/突破 |
| 仅替换引用 | 新旧支持关系及受影响审查 | 重跑全部实验 |
| 关键资料不可达 | 未解问题与影响 | 把“未找到”当“没有” |

任何阶段都可带一个新问题回到本技能，增量查证后回到请求动作。
旧材料继续引用；只有依赖改变的判断需要适用性复查。
状态中的“已检索”不是禁止继续查证的闸门。

## 6. 记录与交付

实际写入遵循 [record-api](../../docs/record-api.md)，不发明工具字段。
每个操作显式提供绝对 `project_root`；新 ID 用 expected_version 0。
有更新时先读取当前版本，追加修订；不覆盖原记录或改写过去范围。
不要把本轮全部全文塞入共享记录，只保存短内容、准确 locator 和 scope。

| 记录 | 保存什么 |
|---|---|
| material | `source/content`；可选 `locator/scope`，保存来源片段或检索报告摘要 |
| activity | 本轮 objective、plan、inputs、status；完成后 result/outputs |
| assessment finding | subject、claim、judgment、evidence、rationale、scope |
| assessment disposition | 对既有反馈/发现的采用、延期、拒绝或替代及输出引用 |

material 没有全局 verified/supports 字段；一份材料可支持一条主张、反驳另一条。
candidate finding 的 claim 必须是那个确切版本已有的 claim_id。
supported/partial/contradicted 必须引用已存在的 material；记录写入不证明已核。
任务相关但未完成的来源核验可记 unknown/unreachable，并说明限制。
不能把身份核验成功写成整项科研主张 supported。
计划/执行/完成是 activity 状态，查新判断是 assessment；两者不要混写。
已经完成才补记的 activity 不得称为事前预注册。

最终输出先回答当前问题，再给：

1. 当前可支持的判断及其范围。
2. 最近邻/关键反例/跨域线索及决定性来源位置。
3. 实际查询、来源状态、日期/截断/访问限制。
4. 尚未回答的关键问题和最便宜的下一动作。
5. 新材料与受影响候选/主张/反馈的准确记录引用。

当前问题已得到足够回答，或预算已到、关键资料不可达时停止。
剩余覆盖不确定性是可交付结果；不为填满卡片继续无边界搜集。
不要自动启动训练、持续监控或全套论文流程。

## 资产来源

保留并改编 RS 的查询视角、原问题对齐、来源提名、正文对照和 delta 写法。
原始资产在 `vendor/research-studio/`；三个方法参考文件列明来源与修改。
参考文件是本技能的现行合同；vendor 是可追溯存档，不执行其旧连接器与席位约束。
