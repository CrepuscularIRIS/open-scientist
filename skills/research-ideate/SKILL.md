# Research Ideate — 生成能继续查证的方向

目标是提出有实质差异的方向，并说明各方向依赖什么、怎样被区分。
它把 Companion 的跨领域探索与 RS 的 gap/pattern 选择接在同一个已定位的问题上。
输出可以是少量机制草案、一个强方向或停止理由，不按数量生产 Card。

## 共同合同与方法资产

先读 [共同研究合同](../../references/contracts/research-contract.md)。
记录方式见 [record-api](../../docs/record-api.md)，不采用原项目固定阶段文件。
跨域与前提挑战读 [Companion 完整 Brainstormer 方法](../../references/methods/companion-brainstormer.md)。
选择机制与组合时读 [RS 完整选择方法](../../references/methods/ideate_select.md)。
模式是帮助识别操作的词表，不是创新分数；只有相关子卡才继续读取。

## 入口与范围

- 问题已足够具体，但团队只想到一种熟悉解法。
- 现有方向可能建立在共同而未核的假设上。
- 有跨领域线索，需要判断是可迁移机制还是只共享名词。
- 两个方向看似都好，需要判断组合是否产生真实相互作用。
- 前一机制失败，但有仍成立的观察或可保留结构。
- 若问题是否存在尚不清楚，先用 [research-diagnose](../research-diagnose/SKILL.md)。
- 若已选定具体机制，只需让它可实现，进入 [research-construct](../research-construct/SKILL.md)。

## 最小输入

| 输入 | 必须保留的信息 |
|---|---|
| Q 版本 | 对象、条件、观察量、stakes、尚未成立的前提 |
| 用户边界 | 明确目标、禁止项、资源事实和未知 |
| 证据 | 最近邻原文、代码路径、数据现象、反例 |
| 可用优势 | 特定知识、真实数据/工具/合作条件，不凭空设定 |
| 过去候选 | 已尝试机制、失败原因、值得保留的部件 |
| 本轮目的 | 发散、补异域机制、查共同前提或检验组合，择实际所需 |

已核事实与推测分别给出；旧总分不是生成新方向的证据。
读取材料索引和关键原文，而不是让润色过的提案成为唯一上下文。

## 有序推理过程

### 1. 重新述明要填的缺口

以失败和目标量重述问题，保留诊断中的适用条件。
先问“什么结果会使这个问题不再是问题”，而非“还可加什么模块”。
若重述时发现问题定义过窄、错误或把唯一解法当 gap，返回诊断。
对用户可挑战的方案提出替代，对硬约束继续遵守。

### 2. 画出当前机制的操作结构

列出对象、状态、可用信息、操作、输出、约束和失败条件。
从真实代码接口检查这些对象是否存在、何时可用、谁能读取。
不要把理论中可见的信息自动给到实际算法。
没有代码时标出待验证接口，不能写成已确认实现能力。

### 3. 寻找结构相同而词汇不同的问题

问另一个领域是否处理相同的信息缺失、选择偏差、耦合、约束或识别问题。
优先提出具体方法/理论线索，不以领域名称排列组合代替解释。
每条映射至少说明源对象→目标对象、源操作→目标操作及成立条件。
明确源机制依赖而目标场景缺少的条件；这可能正是需要研究的障碍。
如果对应只在名词层，保留为联想线索，暂不写成新机制。
文献身份、原文内容与适用范围分别核验；模型记忆提名不是已读事实。

### 4. 挑战共同前提，而不是随机唱反调

从最近邻与代码中寻找被共同继承的默认假设。
说明它为什么曾合理、何种观察可能使其失效。
提出“去掉它会改变哪种预测”，而不是只说“从第一性原理重来”。
将确有不同观察预测的前提交给 [research-test](../research-test/SKILL.md)。
如果所有替代都产生相同观测，先寻找区分方式，不能靠叙事选真相。

### 5. 为候选选择有用的操作模式

按操作签名与适用条件检索 RS 模式，不要求给每篇论文或每个方向贴标签。
选择说明必须是“此操作作用于这个对象，产生某产物，因此填补某缺口”。
同一缺口可以有多个机制家族，避免被问题的表面动词锁定。
无合适模式时可使用自定义机制，不为满足分类而扭曲问题。
旧方法若在同条件下直接解决问题，诚实归为应用/复现或查找真正新增部分。
模式罕见不等于新颖，模式常见也不等于没有实质贡献。

### 6. 检验能否组成一个有意义的候选

从一个承重问题开始，只在实际需要时增加第二操作或 sibling。
串联必须命名中间对象 O，并解释 A 产生 O、B 消费 O 后改变什么。
共同目标、共同数据集、相似故事都不是充分接口。
做移除测试：删掉某部件是否失去核心区分、可验证性或不可缺的功能。
如果删除后只是较小但仍完整，保留为另一个候选或以后工作。
如果组合还需要完全独立的新体系，比较分开验证是否更诚实。
单模式和单缺口是正常结果，无需为简单性辩护。
组合表提供已有例子，不是许可白名单；新组合靠数据流和预测举证。

### 7. 写方向的最小机制承诺

每个保留方向写一句 nugget，随后给出可检查的操作，而不是只有标题。
标记哪些是观察、哪些是解释、哪些是想达到的效果。
给出最朴素替代，说明它可能已经足够或会在哪个条件失败。
列一个关键前提、一个不同于最近邻的预测、一个低成本调查。
尚未有证据的强主张保持为目标，不赋予“已证实”语气。
不默认把所有方向扩写成完整卡片。

### 8. 回查价值与真实优势

用条件式结论检查：若方向成立，会改变什么实际或理论认识。
结合真实可用数据、代码、技能与时间，而非猜测竞争团队的精确完成日期。
保留最强支持与最强反对；对事实争议产生调查项，不用面板多数决定。
没有独特优势不直接证明想法错误；它影响投入排序。
兴趣和表达吸引力可作为讨论信息，不独立决定科研价值。

### 9. 选择要交接的下一动作

机制映射成立但最近邻差异未核：交 [research-retrieve](../research-retrieve/SKILL.md)。
可用信息、接口或现有基线不清：交 [research-code](../research-code/SKILL.md)。
方向已具体且核心条件可讨论：交 [research-construct](../research-construct/SKILL.md)。
核心问题被推翻：返回诊断，并只影响依赖此问题的候选。
需要在候选之间分配投入：交 [research-decide](../research-decide/SKILL.md)。

## 产物：方向包而非一叠长卡

对每个被保留方向记录以下内容，缺失项写未知而不是补造：

1. 问题引用 Q 与一句话机制。
2. 来源机制和目标机制的结构映射。
3. 适用条件、关键断点、最危险的前提。
4. 最近邻与实质差异，附已读材料和待核线索。
5. 朴素替代，以及为什么需要更复杂的东西。
6. 若组合：接口、相互作用预测和移除测试。
7. 条件式价值、真实资源与下一次判别动作。
8. 当前建议：进一步查证、构造、分开保留、搁置或停止。

候选草案作为 candidate；来源作为 material；选择理由和未采用方向作为 assessment。
所有引用使用 `{id, version}`，先写被引用对象再写依赖对象。
相同 Q 下的新机制新建/更新 H；只是表达润色不改机制版本。
提出改变 Q 的方案可以记录，但更改用户明确目标须由用户决定。

## 分支与停止条件

| 条件 | 处理 |
|---|---|
| 仅名词相似 | 保存线索和断点，停止机制包装 |
| 无可用接口 | 保留独立候选或查代码，不硬拼 |
| 发现相同条件已有方法 | 查证包含关系，缩小或撤销创新主张 |
| 只有未知前提决定生死 | 优先查该前提，不继续堆候选 |
| 没有新材料/新预测/不同机制 | 停止发散，明确缺少什么 |
| 缺资源但方向仍有价值 | 交决定，并写可检查的重访条件 |

## 双向交互合同

- 诊断提供问题级失败；发散发现预设解法或无价值 gap 时回诊断。
- 跨域方法提供对象/操作/条件；检索返回同构先行工作时修订差异，不只改标题。
- 代码指出信息不可得时修订 H；若连 Q 的前提都失效，再回诊断。
- 构造暴露新障碍时返回更有针对性的替代机制，而非从零发散。
- 审查返回有效反例时保存反例与可保留部分，避免把旧失败组合进新候选。
- 决定层给出真实投入边界；新边界先影响可行路线，不决定科学真假。
每次交接带待决问题、版本、原材料、允许改动与停止条件。

## 情境例：生态扩散与模型错误传播

用户要求将两个方向组合成漂亮新想法，现有联系只有“传播”一词。
先映射节点、边、状态转移、可观测量与干预接口。
如果生态模型依赖守恒量而目标错误传播无对应量，明确这个断点。
不写“结构完全相同”；查是否有可验证的较弱对应。
若找不到操作对应或新预测，返回映射未成立，保留两个独立线索。
若找到可定义的共享状态量，再让构造技能给出计算方式与区别于朴素基线的检验。
本例描述处理方式，不声称任何生态—机器学习机制已被验证。

## 常见失败与修正

- 为了丰富列十个名词组合：改为少量结构映射和清楚的断点。
- 两个高分所以组合：检查实际接口与删部件后损失的观测。
- 先选模式再找问题：回到失败条件与需要产出的对象。
- 换领域就声称新颖：核对信息条件、操作与已有保证。
- 旧候选失败只换术语：引用原 finding，说明哪项前提或机制真的改变。
- 为吸引读者提前写成功结论：用条件式，并说明必须取得的证据。
