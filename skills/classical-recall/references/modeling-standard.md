# 经典建模标准（原文摘录）

出处：用户手册 `personal-derivations/methodology/2026-11-09_classical-theory-recall-playbook.zh.md` 的 §1（顺序）、§4.2（Q1–Q8 与交付）、§5 步骤 B–F。**原文照录，不改写**；与本插件其他文件冲突时以本文件为准。项目专属的示范书目（§4.2 的 1990 年代示范表）只示范选材标准，不是本项目的方法。

## 1. 我们想保留的研究方式

从一个具体困难出发，Recall 经典理论当初解决的原问题，找到结构上贴切的对象，再一步一步重构成可计算的辅助信号和轻量算法。

这要求同时做到两件事：**联想范围足够广，单次推导足够细。** 广度用于找到候选原问题；深度用于解释一个对象为什么适用、哪里失配、究竟多出什么性质。不能用名词相似或形象比喻替代数学建模，也不要求每个探索中的对象立刻成为完整方法。

本轮最值得长期保留的顺序是：

> 具体困难 → 经典原问题 Recall → 最小图景 → 对象映射 → 要保持的性质 → 数学构造 → 可计算入口 → 跨领域正反例 → groundedness 收敛 → 共同选择下一步。

“保持性质”可以在 Recall 前先给约束，读过原理论后再精确化；文献也可以反过来纠正类比。这是往返推导流程，不是每次必须走完的行政门禁。

### 4.2 高质量经典建模的显式要求

本节将用户“回到经典理论，例如2011年前高质量A会、1997年前后经典论文”的要求落实为后续报告标准。这里约束的是**经典建模报告的质量**；没有满足报告要求，不自动等于研究方向应被KILL。

#### Q1｜时间与原始性：优先追到2010年及以前

默认“2011年前”按**2010年及以前**执行，包括更早的奠基工作。1990年代，尤其1996–1999年前后的文献，是本轮重要Recall入口，不是限定所有理论只能来自这几年。

优先找最早清晰定义相关对象、提出关键构造或建立所用性质的论文。后来的综述、教材和Agent文章可以指路，不能代替核心原始论文。首次版本、正式发表、会议举行和论文集出版年份不同的，分别标明。2011年及以后的重要扩展单列说明，不伪装成早期来源，也不因此拒绝有用的现代迁移证据。

#### Q2｜出处：高质量A会主会优先，奠基期刊明确例外

优先检索相关领域公认的顶级会议正式主会论文，例如ICML、当时名为NIPS的会议、AAAI、IJCAI，以及与问题相关的理论/数据库等领域顶级会议。**这是一项选材优先级，不是已对每个venue完成CCF等级认证。** 如报告使用“CCF-A”标签，须给正式目录及版本依据；不能把现在的分类或会名直接倒推成当年的标签。

重要奠基期刊同样可作为主锚点，尤其博弈论、控制、统计与逻辑中的经典。逐篇写明为什么应保留：它是否定义了所用对象、证明了所用性质、奠定了后续方法。Potential Games即属于这种情形，不能为了满足“A会”字样将其改写成会议论文。Workshop、技术报告、博客和近期arXiv文章单独标类型，不能替代已经存在的正式经典来源。

#### Q3｜经典性：报告“为什么是它”，不只报年代和会名

候选至少回答：它解决了哪个持久的基本问题？哪一个对象、构造或性质后来被持续复用？为什么比一个更近、但只换了应用场景的论文更适合作理论起点？说明这些依据，不设置随意的引用数门槛，也不凭A会身份认定它切题。

#### Q4｜阅读深度：主锚点读到方法和关键性质

深入单对象报告至少有一篇明确的经典原始主锚点，并核读与本题有关的**定义、构造、关键定理条件及证明中的决定性步骤**；注明章节、页码或定理编号。只读摘要时可保留为“Recall待核线索”，不能称为已完成经典建模。无需声称通读全部无关章节，更不能把Pro自报阅读写成Codex独立核读。

原文暂不可得时保留缺口、寻找作者副本或正式版本；不以近期论文的转述补写原证明，不编造年份、venue或定理定位。

#### Q5｜推导深度：复刻“困难如何逼出构造”

每次按同一条链展开：**朴素办法为什么失败 → 引入什么数学对象 → 为什么采用这一步构造 → 得到什么性质 → 前提在哪里被使用。** 势函数、补偿项、条件期望和支持关系应从困难与约束中出现，不能直接空降一个公式。

例如势博弈要解释单方效用变化为什么能由共同势刻画；PBRS要解释局部反馈怎样通过路径抵消控制端点影响。输出一个完整小例子，展示朴素办法、原构造、失效变体的区别。

#### Q6｜迁移深度：明确对应、失配和非平凡增量

逐项映射经典对象与当前历史、动作、观察、Group和终奖。列出至少一处重要失配，并标出我们新增的假设或推导。最后说明类比产生了什么**可计算量、保持性质、误差分解、结构约束或可证伪预测**。如果只得到已有baseline或分析工具，据实保留该用途，不强行命名新算法。

#### Q7｜轻量落地：从构造走到真实入口

写出最少伪代码、信号进入位置、需要新增的信息和四项成本。没有精确Q、语义真值或完整动作支持时，明确替代估计及其误差；不能通过补免费oracle把映射做成。近年训练成功不能代替这一步，纸面保持性质也不能代替经验收益。

#### Q8｜反面校验：给边界，保留正确范围

给一个最小反例和当前最强简单对照。区分“原理论不适用”“迁移推导有误”“该入口无增量”“有限训练未获益”和“尚缺证据”。单一失败变体不否定整个经典家族；有先例不直接KILL，缺先例也不直接KILL。

#### 下一份高质量报告的可见交付

1. 一篇经典主锚点：作者、准确年份、正式出处、原文链接与阅读定位；偏离时间/出处优先级时写理由。
2. 一个原问题和朴素失败例，解释原构造为何出现。
3. 一张对象映射表、一处重要失配、一个完整手算例。
4. 一条明确性质及其条件、一个反例、最轻伪代码与成本。
5. 原理论／迁移推导／猜测／现代训练证据分别标记；结尾指出下一次只解决哪个接口。

以上是深入报告的交付标准；宽Recall阶段可以先产出候选和待核来源。评价核心是建模深度与贴题性，不能用文献数量或会名替代。


### 步骤 B：宽 Recall，只筛对象

给 Pro 问题和可获得量，请它按4.2节的时间、出处和深度标准，从多个经典原问题提出候选。输出“为什么匹配、哪里失配、能导出什么性质”，暂不要求统一算法或好听名称。

把结果分为：优先深入、保留分析用途、暂不贴切。选择理由依据结构与信息条件，不依据领域听起来新不新。

### 步骤 C：一个对象，一个新对话

每个深入对象使用独立 Pro 对话，只给必要共同背景与该对象的问题；允许查经典原论文。新对话用于减少前一类比的锚定，不声称消除了账号级记忆。

先完整复述经典原问题和朴素失败，再讲原构造。之后用同一个小例子映射当前任务。先看形象化过程，再引入最少公式，逐项说明每个变量的来源。

### 步骤 D：指定保持性质，再推算法

每个构造选择它实际承诺的性质：原终奖不变、轨迹排序不变、最优集合保持、原梯度均值保持、指定群组目标梯度正确、局部估计方差改善、或支持状态有效。不能将这些互相替代。

由性质反推需要怎样的抵消、条件独立、终止补偿、支持规则或反事实。标清哪里使用真实量，哪里改用代理，代理不准时首先损坏哪项结论。

### 步骤 E：缩成最小实现

明确辅助量进入：奖励、return-to-go、advantage、baseline、精确补偿项、样本权重、辅助表示损失、上下文状态还是 harness。每项只说明真实改变的路径。

轻量优先从已有 rollout、确定日志、可验证 outcome 和小表开始；必要时再讨论小头。**参数少与计算便宜分别核算。** 成本至少列出新增参数、前向/反向、额外续写与工具结算、结构解析/存储/上下文长度。

### 步骤 F：做第二轮“经典定位与跨域证据”

第一轮可以先形成类比；第二轮回到原理论验证定义、条件和出处，并检验是否只是换名。若一开始映射很弱，就提前检索，不机械等到最后。

跨域查 coding、web、search、工具 agent，以及必要的经典 RL 训练。主动找成功、无增益和退化条件，分别记录训练、推理/harness、toy 与理论。摘要用于定位；关键判定回到方法、主对照及附录，注明实际阅读范围。

尤其检查：收益是否由额外标签、强 teacher、数据筛选、harness 或计算带来；多评估 seed 是否被写成多训练 seed；同训练步数是否被写成同总成本。文献没有覆盖某场景只说明缺口，不能写成已证明失败。
