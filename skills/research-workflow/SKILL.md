# Open Scientist：组织一次有证据的研究行动

研究工作可以从一个疑问、已存在的候选、代码异常、失败实验或需要改写的 Card 开始。先回答“现在什么不确定性阻碍了下一决定”，再选一个能改变决定的动作。不要把研究默认展开成十一项技能的全量流水线。

## 何时进入、何时直接转交

新方向、项目恢复、跨技能交接或用户不知道该先做什么时进入本技能。用户已经明确要求查一条引用、检查一个反例或仅改文案时，保留现有上下文并直接调用相应技能，不追加一次完整 Seed 访谈。

开始前读取 [共同合同](../../references/contracts/research-contract.md)。共享数据的实际字段与命令见 [record API](../../docs/record-api.md)。文中的 Q/H/T 是研究语义，不要求建立额外状态机或服务。

## 两种模式

| 模式 | 何时用 | 行为 |
|---|---|---|
| 单步（默认） | 用户要一个判断、一次检索或下一步建议 | 选一个能改变决定的动作，完成后按操作 6 停下 |
| 自动 | 用户说"自动研究""持续推进""直到交付/达成目标"，或给出交付目标与授权范围 | 按 [自动模式协议](../../references/contracts/auto-loop.md) 循环：一个动作写一个 workflow 检查点，`workflow_check` 未通过、预算未用完、也没有需要用户决定的事项时，继续下一轮 |

自动模式启动时先写 project 与 workflow v1（目标、验收项、授权/禁止、预算），之后每个专项技能完成都不交回用户，而是更新检查点并选下一缺口。只有协议第 3 节的终止条件成立时才停：达成（后端要求验收全部通过才允许 done）、有依据地停止、预算用尽、无进展、越权或需要用户做实质选择。恢复时先读最新 workflow 记录，从 next_action 继续，不重复已记录的动作键。

## 输入：足以选动作的信息

从用户原话与项目材料提取，不要求一次补满表格：

| 输入 | 从哪里取得 | 缺失时怎么办 |
|---|---|---|
| 原问题与希望改变的能力/认识 | 当前要求、原计划、历史决定 | 先看已有仓库/材料，再提出一项必要澄清 |
| 系统/对象与可观察现象 | 数据样例、论文设定、实际代码 | 不用笼统领域名替代问题 |
| 硬约束、偏好、方案猜测 | 用户原话，分别标记 | 方案可挑战，硬约束不可悄悄放宽 |
| 资源事实与授权边界 | 环境记录、已授权动作 | 未知就是未知；先做廉价调查 |
| 当前候选和测试版本 | 项目记录、现有文档 | 没有候选可以先诊断，不造空 Card |
| 已知反证与失败 | 原始输出、审查、退役候选 | 必须保留，不能只读取最高分候选 |
| 当前需要消费的反馈 | 用户新指示、具体 finding | 标明适用对象与版本，记录处置 |

默认检索是本机论文库加 arXiv 关键词。本机论文库不一定覆盖整个领域；查询为空或远端失败不能替代新颖性判断。模型记忆只提出可核验线索。

## 操作 1：定位当前事实，而不是继承旧状态

恢复项目时先读最近的投入决定、候选版本、待处理问题与原始结果目录。已记录 `running`、历史 PID、旧报告中的“已完成”都不能证明当前作业状态。需要查作业时，核对身份、启动时间、命令/调度记录与输出；没有当前访问能力就记未核。

新消息改变硬约束或目标时，将原话和变化写入 project 新版本。保留旧版本以解释为何之前的选择在当时合理。不要凭旧 `ACTIVE` 自动重启计算，不自动购买资源、监控或创建周期任务。

读反馈要有消费结果：采用、待查、不适用及理由。一个反馈文件保存成功不代表下游已经改变了行动。

## 操作 2：判断这是哪种研究任务

| 任务 | 当前要建立的东西 | 优先判别动作 |
|---|---|---|
| 新方法 | 在给定输入与约束下，新增操作解决具体障碍 | 数据流、同条件朴素基线、独特预测 |
| 指标改进 | 相同测量和预算下，改善确实存在且有价值 | 测量审计、等预算对照、重复/不确定性 |
| 竞争解释 | 哪个机制能解释观察，以及何种观察会区分它们 | 明确 rivals、不同预测、可观测量 |

三类任务共用记录与方法参考，但不能都强制套成“提出新网络结构”。也允许研究产物是一项测量修正、限制条件或有效负结果。

## 操作 3：选择最小的下一动作

| 当前阻碍 | 调用入口 | 希望拿回什么 |
|---|---|---|
| 论文/别名/机制出处不足 | [research-retrieve](../research-retrieve/SKILL.md) | 查询范围、原文与主张关系，不是堆篇数 |
| 问题是否真实、失败在哪里不清楚 | [research-diagnose](../research-diagnose/SKILL.md) | 条件、失败、替代解释、价值句 |
| 需要跨域机制、挑战共同前提 | [research-ideate](../research-ideate/SKILL.md) | 操作层映射、断点、不同预测 |
| 概念成立但方法步骤尚不具体 | [research-construct](../research-construct/SKILL.md) | 观测模型、输入输出、朴素替代、H |
| 代码/数据/环境事实未核 | [research-code](../research-code/SKILL.md) | 实际路径、信息权限、测量来源 |
| 需要执行最小判别或内部推演 | [research-test](../research-test/SKILL.md) | T、执行证据、失败分类及边界 |
| 主张、来源、查新或反例有争议 | [research-review](../research-review/SKILL.md) | 有对象/证据/影响范围的 finding |
| 具体失败需要修订 | [research-evolve](../research-evolve/SKILL.md) | Q/H/T 中明确一个变化及复查清单 |
| 已有事实需要 Card/规格/汇报 | [research-report](../research-report/SKILL.md) | 同版本视图与暴露出的真实缺口 |
| 需要投入取舍与恢复条件 | [research-decide](../research-decide/SKILL.md) | pursue/refine/park/kill 与下一观察 |

具体触发与双向回流见 [32 条桥接目录](../../references/contracts/bridges.md)。该目录是可选交互，不是32项任务清单。先前的 Brainstormer 可以参与诊断、构造失败、反例修复和报告缺口，不限于检索前。

## 操作 4：准备一个能被消费的上下文包

对每次行动给出：触发原因、待决问题、引用版本、必须读的事实与反证、允许改变的对象、期望产物。源材料保持可读取地址，不把所有旧报告全文复制给下一个角色。

独立首评用 [审查上下文](../../references/contracts/review-context.md)：隐藏旧分数与推荐结论，保留事实和反例。没有独立上下文时可以自查，但必须称自查，不能用角色名字模拟独立票数。

用户或宿主授权且分工有收益时，可以并行阅读相互独立的资料或做独立首评。依赖前一步答案的动作顺序执行；多个 Agent 不得同时覆盖同一候选。不存在固定模型、必跑三席或两轮配额。

## 操作 5：执行与写回

宿主工具执行检索、读文件、算术与已授权的实验，MCP 只负责项目记录。可用 MCP 的 `records_put/get/list/context/history` 或 CLI，按实际 API 提交；不在 Card 旁边维护第二套相互矛盾的状态文件。

写回时区分原始 material、activity 的实际状态，以及 assessment 的解释。一次命令退出0只代表命令完成，不能推出某个研究主张成立。每条判断标明支持/反驳/仅相关/未知及覆盖条件。

遇到版本冲突先重读当前对象，检查他人的修改，再提出有来由的新版本。用反例修订 H 时保留原始反例及其曾对旧 H 成立的事实。

## 操作 6：在明确边界停止

以下是单步模式的停止规则；自动模式改用 [自动模式协议](../../references/contracts/auto-loop.md) 第 3 节的终止表，完成一个技能不等于该停。

本轮结束至少留下：当前问题、已核与未核、改变了什么判断、下一项可区分行动及停止原因。可以在“问题不成立”“测试当前不可行”“证据尚不足”处结束；无需制造一张看似成熟的 idea card。

下列任一成立应结束当前回路：已回答待决问题；后续动作越过当前授权；没有新证据/新结构/不同预测；触及已知资源上限；应由用户作实质目标取舍。缺资源可 PARK，缺来源转定向检索，事实被推翻回诊断，不将不同缺口统称 KILL。

## 贯穿示例：保存问题变成检索问题

用户认为长程视觉 Agent “记忆被删掉”。先读取现有保存与检索路径，发现保存完整，失败发生在 query 未命中。静态路径只说明可能原因；关联失败实例与调用日志后才可将原因作为已核事实。

更新 Q：从“如何保存更多帧”变为“在已有存储中如何找到决策所需帧”。保留旧论文，但按新用途重新选择。让 ideate 比较信息检索与缓存领域的结构，retrieve 核对源条件，construct 明确可用信号，test 用同存储/同调用预算区分查询与保存解释。

若只看到了代码、还没有对应运行，最终写“检索路径值得优先检查”，不能写“已证明记忆删除不是问题”。若代码已证明旧瓶颈设定错误，则不能继续替旧 gap 生成高分方法。

## 交付检查

- 有没有读实际代码/材料，而只在文献术语里重述问题？
- 原始反例、目标条件和用户新约束是否到达下一动作？
- 选择的行动是否可能改变一个具体决定？
- 是改 Q、H、T 还是只改视图？旧结果有没有被覆盖？
- 下一步是否依据当前授权，PARK 是否留有可检查条件？

## 来源与适配

保留 Research Companion Codex 入口的按需模式、短 Seed、最强正反理由、riskiest assumption 和 pursue/refine/park/kill；将六阶段默认顺序改为问题驱动调用。保留 Co-Scientist 的系统/现象/答案类型目标分解和诚实恢复思想，移除常驻 supervisor、Elo 与预算估计面板的依赖。保留 RS 的证据—机制—探测—修订链，解除固定阶段文件门禁。原文与哈希见 [资产迁移](../../docs/asset-migration.md)。
