# Research Diagnose — 把问题定位到真实对象与条件

本技能负责判断“什么在什么条件下失败、为什么值得解决、现有证据支持到哪里”。
它可从代码、数据观察、文献限制或用户问题进入，不要求先完成固定检索流水线。
诊断的对象是问题 Q；它不预先决定唯一解法 H，更不把拟议结论写成实验事实。

## 共同合同与按需读取

先读 [共同研究合同](../../references/contracts/research-contract.md)。
记录格式和实际命令以 [record-api](../../docs/record-api.md) 为准。
深入瓶颈和谱系时读 [完整诊断方法](../../references/methods/bottleneck_identify.md)。
只有需要跨域前提检查时才加读 [Brainstormer 方法](../../references/methods/companion-brainstormer.md)。
这些长方法保留原项目的推理细节；无需把整个资产库一起装入上下文。

## 适用入口

- 用户说“想让模型更好”，但还没有可观察的具体失败。
- 论文称存在某个限制，当前仓库却可能使用不同信息、默认值或评测条件。
- 提案把“没有某个模块”当问题，已经把解法塞进 gap。
- 检索不足、全文不可得、已有方法包含候选，需要区分缺证据与问题不成立。
- 反例、代码事实或新约束改变了原问题的范围。
- 已有清晰问题，只需改算法细节时，交给 [research-construct](../research-construct/SKILL.md)。

## 输入：本轮必须知道什么

| 输入 | 怎样读取 | 不确定时怎样处理 |
|---|---|---|
| 用户原问题 | 保留原话与明确必须/禁止项 | 区分硬约束、偏好、待测解法 |
| 当前 Q 版本 | 读取 project 与上次诊断/决定 | 没有旧记录可新建起点，不伪造历史 |
| 现象或失败 | 原始样例、输出、日志、统计定义 | 用户报告标报告，尚未复现标未复现 |
| 研究对象 | 仓库版本、实际入口、数据/模型访问 | 未读实现不能宣称代码条件吻合 |
| 文献证据 | 最近邻原文、使用范围、未读部分 | 摘要级残差只作待核判断 |
| 环境资源 | 实际可用数据、权限、算力、时间 | 未知预算保持未知 |
| 先前反证 | 原论断、实例、脚本、结果、适用条件 | 不用摘要或旧评分代替原材料 |

## 推理顺序

### 1. 先把意图分成三个部分

写明用户想理解或改变的现象，以及怎样观察到它。
把明确要求与模型推测分别列出；把“我想用 X”判断为硬要求还是待讨论方案。
未明确时可继续不依赖该区别的只读调查，避免擅自替用户换目标。
如果偏离既有目标是唯一可行方向，先交回具体冲突与备选方案供用户决定。
不要因为当前方案不合理而静默删除用户约束。

### 2. 建立最小证据地图

找到任务入口、数据到模型再到评价的路径，以及一份能定位问题的样例或记录。
只读必要路径，不把仓库总览或模块数量当作理解了失败。
给每项材料注明版本、位置、读到的内容及其支持的主张。
论文描述、代码能力、配置选择、实际运行分别记录。
代码有某功能不证明当前运行启用了它；高分也不能证明信息条件公平。
资料不足时列出最便宜、最有判别力的下一读取动作。

### 3. 把瓶颈写成失败，而不是缺少某解法

使用“在条件 C 下，对象 S 不能获得/维持/区分量 Y，表现为 O”的结构。
若原因尚未建立，把原因写为竞争解释，不把它嵌进事实描述。
“缺持久记忆”指定了治疗；“跨次访问后无法保留可用信号”仍允许不同治疗。
诊断应允许多个机制竞争，而不是让后续 Agent 只能忠实实现第一个念头。
若现象只针对一个系统版本，诚实写出这个范围。
只有证据支持时才将它提升为一类系统的结构性质。

### 4. 核对最近邻真正留下的残差

读方法与限制，回答该工作实际构造了什么、在何条件下做到了什么。
区分论文承诺、作者实现、你运行的实现与评价设置。
必要时补读 anchor 全文或代码，不以获取成功状态替代规则读全。
对研究对象的固定规则，列出可引用原文/代码与尚未固定的参数。
不能把自己选择的隐藏参数当作原系统必然规则。
若关键规则缺失，说明哪些结论依赖猜测，并提出针对性敏感性检查。
没有完整全文时可以继续保留候选诊断，但其残差仍未核实。

### 5. 按需要重建方法谱系

识别基础问题表述、关键方法改动、现有方法仍留下的失败。
同时检查旁系：另一领域是否用不同机制解决相同残差。
谱系的目的，是发现共同继承的前提与已存在的解法，不是填满年代桶。
模型记忆只能提名；若某节点将导致“已做过”的否决，核验其原方法和条件。
不要因为一个旧方法名称相似就排除新条件、不同保证或新的反例。
没有长历史的领域可以只有浅谱系；新观测也可成为 gap 的起点。

### 6. 把“瓶颈成立”本身拆成可核前提

逐条列出：观察确实发生、适用条件成立、基线已经允许合理修复、测量没有伪影。
针对每条说明支持、反对、未知与材料出处。
文献沉默是未知，不是支持；代码变量名也不足以认定泄漏。
找出一条失败就最能改变本轮方向的前提。
将它交给 [research-code](../research-code/SKILL.md)、[research-retrieve](../research-retrieve/SKILL.md) 或 [research-test](../research-test/SKILL.md)。
传完整原材料、待决问题和允许执行范围，不只传一段有说服力的 gap。

### 7. 核对价值，但保持结论为条件式

说明谁遇到失败、付出什么成本，或哪项理论认识/结论因此不可靠。
写“如果 X 成立，将改变 Y，因为 Z”，用于判断值得查证什么。
实践成本与理论成本同样有效；不要求每个问题都能部署。
若只能写“尚无人使用某技术”，还没有建立价值。
一段动听的结论不能替代问题证据；无明确 stakes 时返回定位而非扩写。

### 8. 提前检查是否有可取得的区分证据

找出能区分主要解释的观测，而不是先写完整大实验计划。
已有代码、日志、公开数据、小型例子可能足够，也可能不能代表目标设置。
代理系统能回答什么、不能回答什么必须明确。
缺资源不等于科学错误；问题已解决也不等于资源暂缺。
未知算力不推断为无限预算，不默认训练或启动外部作业。

### 9. 选择最小后续动作

已经有成立且值得查的具体问题：交 [research-ideate](../research-ideate/SKILL.md)。
已有机制草案且仅需澄清兑现方式：交 [research-construct](../research-construct/SKILL.md)。
问题能否成立仍不确定：先查证，不靠增加候选数量绕开。
出现实际代码问题：先处理或定位代码问题，再判断是否仍有科研残差。
需要改变用户指定目标或资源边界：交具体选项，等待相应决定。

## 预期产物与记录

输出一份可继续工作的诊断，而非一定要生成 idea card。

1. 一段问题 Q：对象、条件、失败、当前可观察证据。
2. 事实与前提表：支持/反对/未知及原材料位置。
3. 最近邻差异：已解决什么、尚不确定什么、为什么不是简单复述。
4. 必要时的方法谱系与规则固定表。
5. 条件式价值说明、实际约束和资源未知项。
6. 下一项最便宜的判别动作、接收技能、停止条件。

先登记 project 和 material；用 `assessment` 的 `type=finding`、`subject=project` 与 `evidence` 引用连接问题和材料。
project 本身只有 `question/constraints/user_context/change_note`，不能增加结构化 material 引用字段。
问题定义变更写 project 新版本；评审理由写 assessment，不覆盖旧失败。
如果只是引用修正，不更改 Q；只复核依赖该引用的判断。
后端暂不可用则保存可读交接并说明未入库，不冒充已完成写入。

## 分流与停止

| 观察 | 后续 | 停止本轮的条件 |
|---|---|---|
| 范围太宽 | 少量意图澄清或只读代码定位 | 已有可观察问题，停止补问 |
| 检索失败/无全文 | 定向补来源、标覆盖限制 | 关键证据到手或当前通道不可用 |
| 相关论文少但有真实异常 | 观察驱动诊断 | 已区分现象与待测解释 |
| 相同条件已有解法 | 修正新颖性/任务定位 | 无额外科研残差，交决定 |
| 代码不满足论文前提 | 修订 Q 的适用范围 | 信息路径已核清；未执行仍标未执行 |
| 当前资源不足 | 保留最小代理或 PARK 建议 | 代理无区分力则不继续包装 |
| 问题不成立/不值得 | 撤销该诊断，保留教训 | 没有新证据或不同问题可推进 |

## 双向桥接与版本边界

编号与 [桥接合同](../../references/contracts/bridges.md) 一致：

P1-1：Seed/Goal 的约束输入本技能；约束冲突返回用户，模型方案可自行修订。
P1-2：Frame 的条件式价值输入 stakes；真实残差改变后反向修订预期贡献。
P1-3：Brainstormer 的结构类比进入谱系；已占据方法返回检索与候选差异。
P1-4：代码/前提审查可以推翻文献 gap；更新 Q 后仅重开依赖它的 H/T。
P1-5：将缺文献、锚点、资源、可观测量与价值分别分流；少文献不等于无价值。
P1-6：后续反证回到最小影响范围；解法失败只改 H，问题前提失败才改 Q。
补充边界：资源限制只改变测试路径时写新 T；若必须改变用户目标 Q，交用户决定。
报告返回缺失定义时辨认 View/H/Q，不能通过润色暗中改机制。

## 情境例：高分实现用了 oracle labels

论文瓶颈是推理时缺少标签信息，代码报告很强分数。
先检查标签加载、可用时点、进入决策/损失/评价的路径及运行配置。
若标签只用于训练监督，它未必违背推理条件；继续核实际测试分支。
若测试决策确实读取目标标签，则该分数支持 oracle 条件，不支持目标场景。
记录论文前提与实际信息条件的差异，并把原分数限制到正确范围。
在授权内提出去 oracle 的最小检查；不要默认开始扩大训练。
此时可自行修正待核诊断，不能替用户把目标改成 oracle 系统。

## 常见失败

- 用缺模块替代问题：重写成失败量与条件，再允许不同解法。
- 把全文抓取成功当规则完整：列实际读到的规则和未固定项。
- 把模型谱系回忆当已核先行工作：只有决定性使用时定向核验。
- 把大段理想结论当证据：保留条件式与需要取得的观察。
- 把不可行、无价值、已解决混成 KILL：分别给出科学判断与投入建议。
- 为了完成卡片忽略代码反证：允许诊断撤销并终止该方向。
