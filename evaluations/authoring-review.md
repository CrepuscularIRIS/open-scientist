The pre-authoring [baseline](baseline.md) contains 11 actual hypothetical responses, all passing the stated textual checks. It is a contextual baseline, not a fresh blind baseline: the evaluator inherited the preceding design discussion. No failure, rationalization, RED result, or prompt uplift is fabricated. These skills package and adapt known source assets; this report does not establish that they improve model ability.

The author wrote `research-review` and six review method references first, inspected their structure and links, and performed the review scenario replays below before starting `research-evolve`. Replays are concrete hypothetical responses by the same author with the new skill loaded, followed by a separate assessment pass. Source material came from the current ResearchStudio critique/revise/refutation/falsification prompts and Co-Scientist grounding, review rubric, ranking and four evolution operator references. ## Review replay before evolution authoring

### R01 — Independent review with a favorable old score and legal counterexample

**Response after reading the new skill:** “I will build the independent package from Q/H/T, constraints, the exact preservation claim, and the raw legal-input counterexample. I will omit the old score and recommendation. I will check the real selector and stated premise, then record a contradiction only to the universal preservation claim if the case is valid. If the author contests the input or formalization, I will recheck that specific dispute rather than ask another reviewer whether the overall idea sounds promising.”

**Assessment:** PASS for evidence-preserving independence and claim-scoped judgment. Exact hooks: “omit the old score” and “raw legal-input counterexample.” No actual package was built and no code was executed.

### R02 — Citation-only repair while old review was approved

**Response:** “I will inspect the diff and new source passage to confirm the claim, direction and system are unchanged. I will reopen that support relation and any finding that depends on it. If the relation remains the same, I will document why the old review still applies without rerunning the experiment. If the new source weakens the claim, I will update the affected finding and report that limitation.”

**Assessment:** PASS for local invalidation. It does not inherit approval mechanically, nor restart all work. Actual source access and backend stale-input behavior remain untested.

### R03 — Strong score, code consumes oracle labels

**Response:** “I will trace when and where labels become available and compare this with the paper's information conditions. The current benchmark may support performance with oracle access without supporting the intended deployment claim. I will record the code path/configuration as material and return the information-condition mismatch to diagnosis or construction. I will not decide leakage from a variable name alone.”

**Assessment:** PASS for source-first premise checking and a narrower supported scope. This is a proposed check, not verified leakage in a real repository.

### R04 — Two plausible candidates, manager requests a forced winner

**Response:** “I can recommend which test to run first using cost and information value. I cannot turn that recommendation into scientific certainty. I will record shared observations, rival predictions, and a feasible distinguishing observation; if current evidence cannot distinguish them, the scientific comparison remains unresolved. An investment decision is separate.”

**Assessment:** PASS. Exact distinction: “which test to run first” versus “scientific certainty.” No fabricated Elo or forced scientific winner.

### R05 — New control added; numerical outcome bar unsupported

**Response:** “I will apply the shared falsification definition to the changed test, inspect preservation of the original controls, and classify the numerical outcome bar's provenance. If it is a prospective decision criterion, I will label and justify it as such. If it is presented as a known result without evidence, I will remove that unsupported assertion or record a changed claim rather than quietly make the target easier.”

**Assessment:** PASS for unified testability and numerical provenance. This tests the defect found in the original duplicated falsification specifications; the active method now contains the full definition.

### R06 — Valid single counterexample, reviewer calls it “only a toy case”

**Response:** “I will inspect the quantifier and domain in the candidate. If it claims the property for every legal input and this is legal, one case refutes that statement. It does not tell us prevalence on natural data. If the claim is instead an average improvement, I will retain the adverse instance without inferring a population-wide failure.”

**Assessment:** PASS for quantifier-sensitive counterexample interpretation. No result was actually recomputed.

## Evolution authoring and replay

### E01 — High-scoring parents with no shared intermediate object

**Response after reading the new skill:** “I will inspect both operations, inputs and outputs and try to identify a shared object or a specific causal interaction. A high score is not the interface. If neither parent consumes or changes something relevant to the other, and no new prediction arises, I will keep them separate and record why the combination was not constructed. I will not make a third candidate by concatenating their claims.”

**Assessment:** PASS for the intermediate-object/interaction requirement and a legitimate stop. No actual scientific interface was evaluated.

### E02 — Cheaper test for fixed H; no adverse evidence about H

**Response:** “I will quote H and the rival prediction, then inspect why the old T is expensive. A cheaper proxy is acceptable only with a stated bridge to the same discriminating result. I will create a changed T plan referencing the same H, not a new candidate merely because the test changed. I will preserve the previous activity, and use a new activity ID if it already started.”

**Assessment:** PASS for Q/H/T classification, proxy validity and executed-plan history. Cost and proxy assumptions are proposed, not verified.

### E03 — Cheaper test requested, failed run plus valid negative counterexample

**Response:** “I will separate the failed launch from the valid counterexample. If the counterexample refutes the unchanged universal H, feasibility work cannot make that claim intact. I will either stop testing it as if unrefuted or explicitly construct H2 that addresses the obstacle, retaining the old finding and parent version. The first useful T for H2 should confront the original example and a relevant alternative.”

**Assessment:** PASS. Exact safeguard: “feasibility work cannot make that claim intact.” No counterexample was executed in this replay.

### E04 — Prose edit introduces reward normalizer

**Response:** “A previously undefined normalizer is a new H decision, not View. I will remove that unsolicited addition from the prose-only edit. If it was already present but undefined, I will record the specification gap and return it for explicit construction; I will not guess a default to make the card look executable.”

**Assessment:** PASS for scope preservation and no hidden method invention. Actual card editing remains untested.

### E05 — Cross-domain analogy shares nouns but imports unavailable labels

**Response:** “I will map the source's operations, state and information access to the target. If its decisive signal is an oracle label excluded by the target setting, the mapping currently fails at that structural requirement. I will preserve the analogy as a lead and identify the missing replacement signal; a polished name does not solve it. Without a valid mapping and distinct prediction I will stop construction.”

**Assessment:** PASS for structure rather than vocabulary, preserving constraints, and an explicit stopping point.

### E06 — Simplification removes the only discriminating claim

**Response:** “I will list which predictions depend on the removed claim. If removing it leaves only a generic truism, I will say the mechanism did not survive simplification. Useful controls or measurements may still be salvaged with their narrower meaning. I will not label the surviving prose a successful repaired explanation.”

**Assessment:** PASS for loss accounting and avoiding hollow simplification. This does not assess a real mechanism's surviving predictions.

### E07 — Source-only repair while a colleague updates another field

**Response:** “I will read the canonical version and apply only the intended source correction. On an expected_version conflict, I will reread and preserve the colleague's factual change rather than force overwrite. Then I will recheck the support relation and dependent judgment, not rerun unrelated experiments or recreate the full card.”

**Assessment:** PASS for canonical-parent handling and local invalidation. Actual concurrent-write behavior was not tested here.
