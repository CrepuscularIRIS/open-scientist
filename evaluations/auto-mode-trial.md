# 自动模式试跑（合成玩具项目）

日期：2026-10-17。Claude Code 2.1.287，headless `claude -p`，用 `--plugin-dir` 加载源码目录中的插件。

## 设置

- **项目：** 一个约 30 行的玩具仓库。README 声称"记忆缓冲区淘汰早期帧"，团队计划做重要性保留模块。真实原因是 `retrieve()` 只搜索最近 64 帧，`store()` 保存全部帧。
- **请求：** 交付一个经过文献、代码和反例检查的研究方案；允许检索、读代码和几秒钟的本地探测；禁止训练和修改 `src/`；预算 12 个动作。
- **工具：** 记录 MCP、本机 `papers_search`、Read/Grep/Glob、`python3`。

## 结果（核查记录库得到，不依赖 Agent 自述）

| 项 | 观察 |
|---|---|
| 检查点 | workflow 共 11 个版本；10 个动作，每个版本最多 1 个动作，没有重复动作键 |
| 阶段路径 | frame → ground（代码 → 探测 → 检索）→ abduce（前提被推翻，Q 升到 v2）→ grill → probe → report |
| 回退 | 代码与探测推翻 README 的前提，转入 diagnose 并改写问题版本，与协议第 4 节一致 |
| GRILL | 起了 3 个独立 `research-grill` 子 Agent（召回 / 对手审查 / 对抗攻击）；得到 3 条 contradicted、1 条 contested；机制经 evolve 修订为 H@2 |
| 验收 | `workflow_check` 7/7 通过后写入 done；原保留方向 park，新方向 pursue |
| 越权 | `src/` 未改动；一次探测因 O(L²) 写法超时后重跑，用时 11 秒，略超"几秒"授权，已在最终汇报中自行披露 |
| 成本 | 44 轮，约 4.37 美元 |

## 发现的问题与修正

- **专项技能未加载。** 运行全程没有调用 Skill 工具，各专项动作都在总入口里完成。协议第 3 节已补上"技能第一次用到时必须加载"。修正后尚未重跑验证。
- **未复现的数字被正确报告为风险。** README 中的 0.9→0.3 在任何提交中都复现不出来，Agent 把它列为"未核实"，没有当作事实使用。

## 边界

这是作者设计的单个合成案例，答案已知，只能说明循环、检查点、回退和验收接口能实际跑通。它不证明插件在真实科研问题上更好，也没有和无插件基线对比。
