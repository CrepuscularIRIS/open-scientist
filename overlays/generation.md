2. **Classical construction (the solution-side core).** `phase1/classical_anchors.json` → `order` lists classical anchors modeled to the user's Q1–Q8 standard (original problem → construction → preserved property and its conditions → mapping with mismatch). One added constraint: the chosen pattern / sub_pattern must not contradict the anchor's construction or break its conditions; if none fits without contradiction, use `sub_pattern: null` and say why.
3. **Intervention object.** `intervention_object` must name the concrete code object the method changes (module / function / input / loss term). The card-level soundness verifier reads it against the code.
4. **Keep the claim minimal.** State the mechanism on the target bottleneck itself. Do not widen it to a class of problems unless that changes the experiment.
5. **Prior work is not a penalty (user 2026-11-08).** This is an integration/application paper: a similar method existing in the literature does not demote an anchor or a candidate; it only names the nearest work to cite and compare against. Change the anchor only if existing work already solves the target bottleneck itself (not an adjacent problem).
